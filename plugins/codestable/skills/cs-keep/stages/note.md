# cs-keep · note

## 用途与边界

将用户要求保留的短小、稳定、经常用到的项目事实写入 `.codestable/attention.md`。遵循项目入口约束；读取待修改文件并复用已加载上下文，不重复请求记录授权。

| 信息 | 归宿 |
|---|---|
| 简短、长期生效、多数任务需要知道的命令或约束 | `attention.md` |
| 详细背景、坑因和修法 | `cs-keep learn` |
| 特定库或任务的操作方法 | `cs-keep trick` |
| 需要记录选型理由的已批准决定 | `cs-keep decide` |
| 临时状态或 workaround | 相关 issue / feature 记录 |

例如：构建前需要生成 schema、项目包管理器、有效测试命令、报告语言策略、凭据获取方式。记录凭据来源，不能把凭据值写入项目文件。

根据已知用途自主选择归宿，不为分类本身询问。只有规则含义、长期有效性或新旧约束存在实质冲突时才请 owner 裁决；未获授权的新规则不能自动成为持久约束。

例外：仓库已有 `.codestable/attention.md` 时，owner 亲口说出的、跨任务有效的范围或授权规矩（只做谁的部分、不建 PR、不合并、不推哪个分支、不碰哪些目录），这句话本身就是记录授权。当场写入并用一句话告知；owner 把同一条规矩说到第二遍，说明第一遍就该记。只管当前 unit 的规矩写进该 unit 的记录，不进 `attention.md`；只管这一步的指示不记。owner 没说原因就照实写"owner 指示，未说明原因"，不编造、不追问。

## 目标与结构

默认目标是 `.codestable/attention.md`。用户点名本技能或明确要求写入 `attention.md` 时，缺少目标文件可创建最小内容，无需先运行完整 onboard；上面的范围 / 授权例外不创建这个文件。项目已有结构优先，不自动改写 `AGENTS.md` / `CLAUDE.md` 等入口；仍须遵循其中有效约束，用户明确指定其他目标时按请求处理。

新建时可选用以下分节；无需插入空节或固定整套骨架：

```markdown
## 项目碎片知识

<!-- cs-note managed -->

### 编译与构建
### 运行与本地起服务
### 测试
### 命令与脚本陷阱
### 路径与目录约定
### 报告语言策略
### 范围与授权
### 环境变量与凭证
### 其他
```

已有 `<!-- cs-note managed -->` 注释可用于定位；缺少锚不代表需要追加重复骨架。必要时自主增加简短类别，不因分节或条数索取审批。保持启动上下文简短：长背景和低频说明放相关记录并用链接指向，不擅自删除有效约束。

"不要 / 禁止 / 必须先问"这类条款写明适用的具体动作和原因，模型会照字面执行，范围写宽了会连正常工作一起拦住。原因已不成立的谨慎条款向 owner 提出删除。`attention.md` 超过约 25 条或单条变成长段落时，先合并或移走低频内容再新增。

## 执行

1. 依据用户请求和已知事实确定条目及归宿；需要其他记录技能时，在已有授权内继续，不只返回技能名称。
2. 读取目标当前内容并定向查重。相同事实复用；同一规则的明确更新直接修改原条目，不机械追加。
3. 写入授权的条目，每条通常一两行，含事实和必要原因。可一次处理多条已确定事实，不顺便添加未授权规则。
4. 核对差异、重复、链接和与已有规则的冲突，完成后简要说明结果，无需再次要求确认已请求的记录。

条目示例：

```markdown
- 编译前运行 `pnpm run gen`，否则 schema 类型不同步。
- 使用项目的 yarn berry 锁文件，不运行 `npm install`。
```

## 何时建议记录

只在发现有持续价值的新项目事实时简短建议；用户已经要求记住则直接执行。除上面的范围 / 授权规矩外，没有记录授权时不自动落盘，用户拒绝后不重复建议。

避免把临时任务状态、详细指南、重复规则或尚未拍板的方案放入启动上下文。
